## 2024-05-24 - Perlin and Value Noise Math Function Extractions
**Learning:** For extremely hot loops in procedural generation (Perlin noise and Value noise), leaving mathematical helper functions (fade, lerp, grad) attached to exported objects (like `Noise.fade` or `CLOUD_NOISE.smoothstep`) adds significant property access overhead. Also, deeply nesting them or inlining them into single giant expressions can cause V8 de-optimizations (like spilling registers or failing to JIT effectively).
**Action:** Extract hot helper methods out to module scope functions. Specifically, for Noise 3D generation, defining simple `grad` and `lerp` functions at module level and extracting the `noise3D` function to the module level while keeping `fractal` logic straightforward yields ~20% performance improvement (134ms -> ~107ms). For Cloud Noise (fbm2D), extracting the inner `valueNoise2D` logic slightly and reducing repeated multiplications cuts time by ~10% (100ms -> 94ms).
